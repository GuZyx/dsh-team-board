# 协作任务板 / Team task board

## 它做什么

Agent Teams 的共享任务有内置的只读弹出面板（会话头部 → Subagent → 共享任务）。这个插件把同一份数据做成一个**独立的左侧栏页面**，适合盯着看多条任务并行时的整体形状。

数据来源是 Harness 已有的 `agentTeam` 会话投影，本插件**不写 Host 侧代码、不改投影、不新增 Remote**，Host 半边是空的（`export function apply() {}`）。

## 用在哪

左侧栏 → 协作任务板（排在「自动化任务」下面）。打开后：

- 顶部：页头标题 + 构建号、当前会话标题、视图切换下拉、Team 模式徽标、自动刷新间隔、刷新按钮。
- 下拉三种视图：**全部会话**（聚合总览）/ **跟随当前会话** / **钉住某个会话**；每个会话项后面带它的任务计数。
- **子智能体区**（排在任务区上方，与内置 Subagent 面板同源）：每个成员一行，显示标题、agent 名、累计 token（`180K tok` 这种量级）、耗时（`16秒` / `11分49秒`），运行中的用蓝色状态点并每秒走时。点成员行展开 token 四项明细（输入/输出/缓存读/缓存写）与会话 id。数据来自根会话的 `subagentCatalog` 投影 + 每个子会话的 `tokenUsage` / `subagentTiming`；查看子会话时会向上找到根，所以兄弟成员照样显示。
- 工具栏（仅单会话看板）：按标题/描述/负责人/写域搜索，快捷过滤「只看被依赖阻塞」「只看写域冲突」，按负责人下拉筛选，一键清除，右侧显示 `筛选后 n/总数`。
- 指标条：单会话视图显示被依赖阻塞数 + 完成率；全部会话视图显示任务总数（含会话数）+ 被依赖阻塞 + 完成率。三列的条数由列头自己显示，不重复占版面。
- 三列看板：待处理 / 进行中 / 已完成。
- 卡片：标题在上，id 与负责人在下方 meta 行；**点卡片展开**完整描述、写域路径、写域冲突原因、被哪些任务阻塞（带对方标题与状态）；**点依赖项直接跳到那张卡**并高亮；点负责人名字即切换「只看该负责人」。
- **依赖箭头**：`blockedBy` 关系用虚线贝塞尔曲线从阻塞方连到被阻塞方，带箭头。只给「真的在等」（`status=pending` 且 `ready=false`）的任务连线；同列走列外侧弧线，右列阻塞左列时从外缘绕行，不横穿中间列。列内滚动、窗口缩放、卡片展开都会触发重新测量。全部会话视图不画箭头——跨会话的依赖没有意义，每个团队是独立的图。
- **写域冲突**：`writeScopeWarnings` 非空时卡片边框变黄并显示「写域冲突 N」，展开后列出具体冲突文本。

## 键盘

页面内（非输入框）：

| 键 | 作用 |
| --- | --- |
| `↓` / `j` | 光标移到下一张卡（自动滚动到可见） |
| `↑` / `k` | 上一张卡 |
| `Enter` / `Space` | 展开/收起当前光标的卡 |
| `Esc` | 收起详情并清除光标；在搜索框里则移出焦点 |
| `/` | 聚焦搜索框 |
| `g` | 在「跟随当前会话」和「全部会话」之间切换 |
| `r` | 刷新 |

## 视图记忆

视图（跟随/总览/钉住哪个会话）、搜索词、两个快捷过滤、负责人、自动刷新间隔都写进 `localStorage` 的 `dsh.team-kanban.v1`，重新打开面板或刷新页面都会恢复。记住的会话若已不存在会自动回落到「跟随当前会话」。自动刷新可关（默认关）/10 秒/30 秒，只在面板挂载期间计时。


## 多会话怎么算的

Agent Teams 的板子属于**根会话**，不存在一块全局板子。所以"多会话"是多个团队并列，不是一张更大的图。

- **下拉计数**：有上限的批量预热——只对列表最靠前的 8 个会话各发一次投影读取，其余会话在你选中时才加载。已经打开过的会话直接从内存里的投影取值，不额外请求。
- **全部会话总览**：按会话分组汇总，只聚合"已加载且真有非删除任务"的会话；每组有计数和一个「打开」跳回单会话视图。底部注明已加载/总会话数。
- **成本**：投影是逐个会话请求的，冷会话要走存储的头部/检查点（不唤醒 agent）。所以预热窗口刻意压到 8，不会因为会话多就发几十个请求。


## 只读

看板没有任何写操作按钮。认领、完成、改依赖只能由 agent 通过 `team_task_*` 工具完成——这一点和内置面板一致，因为任务变更必须走 CAS 和会话日志。

## 状态机

五种互斥状态，不会出现"永远转圈"：

| 状态 | 触发条件 | 表现 |
| --- | --- | --- |
| 加载中 | 首次请求该会话投影 | 正在加载任务板… |
| 不可用 | 加载结束但仍没有该投影 | 任务板暂不可用 + 重试 |
| 记录无效 | 投影自带 `failure`，或投影行 state 为 error | 任务记录无效：原因 + 重试 |
| 协作未开启 | 投影存在且 `enabled=false` | 提示去根会话模型菜单开「启用智能体团队协作」 |
| 正常 | 投影存在且已开启 | 指标条 + 三列看板 |

刷新按钮是真动作：清错误、置加载中、重新请求，成功失败都有可见结果。切换会话会丢弃上一个会话的错误与选择。

## 限制

- **一次只画一张图**：单会话视图才画三列 + 依赖箭头。全部会话视图是分组的卡片列表（每组可能几十条任务，画不下箭头），要连线就点「打开」进单会话视图。
- **子会话的任务区是空的**：子会话没有自己的协作模式，切到子会话会显示"协作未开启"——要看得回到根会话。子智能体区不受影响，它会向上找到根会话的目录。
- **成员行不能打开子会话**：内置面板点成员会跳到那个子会话，这里只展开 token 明细和会话 id。客户端没有公开的"打开指定会话"入口，硬用内部导航 API 会把插件绑在更脆的字段上。
- **成员的 token 与耗时来自列表摘要**：`byId[id].projectionValues.tokenUsage / subagentTiming`，宿主没算出来的成员显示 `—`。
- **总览有加载边界**：只有已加载的会话进入聚合；没加载的会话不会自动出现在总览里（避免一次拉几十个会话的投影）。想要全量就把下拉里的会话逐一点一遍。
- **依赖箭头是尽力而为的**：卡片位置靠 DOM 测量维护，只覆盖常规布局；卡片位置若因字体异步加载而变动，曲线会等到下一次 resize/scroll 才对齐。
- **筛选只在单会话视图生效**：总览是按会话聚合的，组内过滤和组间过滤语义会打架。
- **文案只带中英两种**，面板内文案走插件自带字典（措辞对齐内置面板），插件条目的标题/描述走标准 `locale/*.json`。
- **写域冲突只提示不拦截**：`writeScopes` 本来就是建议性的，重叠只告警。
- **面板内套了错误边界**：单次渲染异常退化成面板内的一张错误卡 + 重试，不会把主区域打白，也不会让槽位条目退役。

## 数据接口依赖

公开契约优先，必要时降级：

- **投影数据**走 `main` 槽自带的 `useSessions` 选择器钩子（Harness 公布的标准 props），只取 `state.projectionsBySession[sessionId].values.agentTeam` 这一片，变更由框架推送。
- **首次加载与刷新**用 `ctx.sessions.refreshProjections(sessionId)`。
- **会话下拉**同样来自 `useSessions` 的快照（`items` 或 `ids`+`byId`）。
- **当前会话**没有标准 prop，读 `ctx.uiWorkspace.mainReference`，回退到 `ctx.uiWorkspace.selection` 快照并订阅它的变化。这是本插件唯一依赖内部字段的地方。

所有读取都包了 try/catch：Harness 升级后若字段变化，插件退化为显示提示文案，不会把槽位打白。
